# 远程开机（巴法云 + 网络唤醒）

人不在电脑旁边、路由器也没有公网 IP 时，用手机远程把家里或宿舍的电脑开起来。

路由器在校园网 NAT 后面，外面连不进来；所以反过来，由路由器主动连到巴法云（bemfa.com，国内物联网平台，免费）并订阅一个主题。手机在巴法云 App、微信小程序或米家（小爱同学）里向这个主题发「on」，云端把消息推给路由器，路由器再向 LAN 口广播网络唤醒（Wake-on-LAN）魔术包，电脑就开机了。

- 只有一条从路由器出去的 TCP 连接（`bemfa.com:8344`），不开放任何端口，不改防火墙规则
- 一个巴法云账号最多同时唤醒 8 台电脑（单次订阅最多 8 个主题）
- 只认「on」指令；「off」不会关机（路由器没法替你关机）
- 可接入米家 / 小爱同学，并把电脑真实的开关状态同步回米家
- 重连时不会补收历史消息，断网恢复后不会误开机；同一台电脑 5 秒内的重复指令只执行一次

## 准备电脑

网络唤醒要求电脑**用网线连接路由器**（Wi-Fi 网卡基本不支持），并且关机后网卡仍然通电：

1. **BIOS / UEFI**：开启 `Wake on LAN`、`Power On By PCI-E`、`Resume by PCI-E Device` 之类的选项（各主板名称不同）；有 `ErP` / `EuP` / 深度节能选项的要关掉，否则关机后网卡断电。
2. **Windows 网卡属性**（设备管理器 → 网络适配器 → 有线网卡 → 属性）：
   - 「电源管理」：勾选「允许此设备唤醒计算机」和「只允许幻数据包唤醒计算机」
   - 「高级」：`Wake on Magic Packet` 设为「开启」；如有 `Shutdown Wake-On-Lan` 也要开启
3. **关掉 Windows 快速启动**（控制面板 → 电源选项 → 选择电源按钮的功能 → 取消「启用快速启动」）。开着快速启动时，很多网卡在「关机」后不响应魔术包。
4. 记下有线网卡的 MAC 地址：`ipconfig /all` 里「物理地址」那一行。路由器 LuCI 页面的下拉框里也能直接选当前在线的设备。

睡眠（S3）和休眠（S4）状态通常比完全关机（S5）更容易唤醒。断电后（拔插头、跳闸）网卡没电，无法唤醒。

## 准备巴法云

1. 打开 [cloud.bemfa.com](https://cloud.bemfa.com/)，用微信扫码登录。控制台左上角显示的就是**私钥**（UID，一串字母和数字），复制下来。这串私钥相当于密码，不要发给别人。
2. 进入「TCP 设备云」，新建主题，例如 `pc001`。**以 `001` 结尾的主题会被识别为「插座」设备**，这样才能接入米家、用小爱同学语音控制。可以给主题起个昵称，比如「电脑」。
3. 想要多台电脑，就再建 `laptop001`、`nas001` 之类的主题，一台电脑对应一个主题。

## 在路由器上设置

LuCI「服务 → 远程开机」：

1. 「私钥」填巴法云私钥。
2. 在「电脑」表格里点「添加」，填名称、选择或输入 MAC 地址、填巴法云主题（如 `pc001`）。
3. 勾选「启用」，保存并应用。「运行状态」显示「已连接，随时可以远程开机」即可。
4. 页面最上方的「开机」卡片会列出每台电脑的开/关机状态，点「开机」确认电脑在本地能被唤醒。这一步直接从路由器发魔术包、不经过巴法云，失败就说明电脑或网卡设置还有问题，先按上一节排查。

命令行等价操作：

```sh
uci set remote-wol.main.uid='你的私钥'
uci set remote-wol.main.enabled='1'
uci add remote-wol host
uci set remote-wol.@host[-1].name='我的电脑'
uci set remote-wol.@host[-1].mac='AA:BB:CC:DD:EE:FF'
uci set remote-wol.@host[-1].topic='pc001'
uci commit remote-wol
/etc/init.d/remote-wol restart
/usr/share/remote-wol/wake AA:BB:CC:DD:EE:FF   # 本地手动唤醒
cat /tmp/remote-wol/status.json                # 连接状态和最近 10 次唤醒记录
logread -e remote-wol                          # 日志
```

## 远程开机

任选一种：

- **iPhone App「远程开机」**：见下文「iOS App」。
- **手机网页**：见下文「远程开机网页」。
- **米家 / 小爱同学**：见「接入米家 / 小爱同学」。
- **巴法云 App / 微信小程序「巴法云」**：找到主题 `pc001`，点「开」（发送 `on`）。
- **巴法云控制台**：在 cloud.bemfa.com 控制台对主题发送消息 `on`。
- **自己写脚本 / 快捷指令**：`https://apis.bemfa.com/va/postmsg?uid=私钥&topic=pc001&type=3&msg=on`（巴法云 HTTP 接口，`type=3` 表示 TCP 设备云；具体参数以巴法云文档为准）。

## 远程开机网页

固件自带一个手机网页：`http://路由器LAN地址/remote-wol/`（默认 `http://192.168.1.1/remote-wol/`，LuCI「远程开机」页面也有链接）。

- 第一次打开填巴法云私钥并保存，私钥只存在这台手机的浏览器里，不会发给路由器或巴法云以外的地方。
- 列出巴法云「TCP 设备云」里的每个主题（每台电脑一个）：开机 / 关机状态、多久前更新、路由器是否在线，点「开机」就发送开机指令。发出指令后两分钟内每 5 秒刷新一次，能看到电脑变成「已开机」。
- 「检查巴法云」按钮：排查米家里看不到设备的原因，见下文。
- 网页直接调用巴法云的 HTTP 接口（`allTopic` 读状态、`postJsonMsg` 发 `on`），巴法云允许浏览器跨域调用，所以网页本身放在哪里都能用。固件里这份只能在局域网打开；人在外面时用 iOS App。

## iOS App

仓库里的 `ios/` 是一个 SwiftUI App「远程开机」，功能和网页一样，另外支持 Siri：

- 电脑列表、开 / 关机状态、路由器在线状态、一键开机，下拉刷新。
- 「检查巴法云」诊断米家问题。
- Siri / 快捷指令：说「用远程开机打开电脑」或「远程开机开机」。在设置里可以选 Siri 默认开哪台。米家用不了时也能语音开机。
- 私钥存在 iOS 钥匙串（仅本机），不随备份迁移。

构建：GitHub Actions「Build iOS app (unsigned IPA)」在 macOS 机器上用最新 Xcode 编译，先在模拟器里跑单元测试，再输出**未签名**的 `RemoteWOL-x.y.z-unsigned.ipa`。最低支持 iOS 17，iOS 27 上可直接运行。

安装：用你自己的证书重签名后安装，例如 Sideloadly、AltStore、爱思助手或 `zsign`。包标识是 `com.rm2100.remotewol`，可以在重签时改成你证书允许的标识。App 不需要任何特殊权限（entitlements）。

## 接入米家 / 小爱同学

1. 在巴法云控制台「TCP 设备云」里建好以 `001` 结尾的主题（如 `pc001`，`001` 表示插座类设备），点主题旁的「设置」把**昵称**改成「电脑」。昵称就是米家里的设备名，也是小爱同学认的名字。
2. 在路由器 LuCI「服务 → 远程开机」里填同一个主题，保存并应用，等「运行状态」显示已连接。
3. 打开米家 App：「我的」→「连接其他平台」（旧版叫「其他平台设备」）→「添加」→ 选择「巴法」→ 用巴法云账号登录授权 →「同步设备」。
4. 米家设备列表里出现「电脑」插座后，点开关就能开机，也可以说「小爱同学，打开电脑」；还可以把它加进米家的自动化和场景（比如「到家前 10 分钟开电脑」）。

在巴法云里改了主题或昵称后，要回米家里再「同步设备」一次。天猫精灵、小度音箱也有巴法云技能，用法类似。

### 米家里看不到设备

先在 LuCI「远程开机」页面、手机网页或 iOS App 里点「检查巴法云」，它会用私钥查询账号下的主题并逐条给出原因。常见原因：

1. **主题名后三位不是设备代码**。只有以 `001`（插座）、`002`（灯）、`003`（风扇）、`004`（传感器）、`005`（空调）、`006`（开关）、`009`（窗帘）结尾的主题才会同步到米家，`pc`、`computer` 这类名字不会。电脑用 `001` 或 `006`。
2. **主题没在巴法云控制台建**。路由器订阅一个主题不会自动在控制台创建它；LuCI 里的检查会指出「路由器里填的主题在巴法云里不存在」。到控制台「TCP 设备云」新建同名主题。
3. **建在了别的云里**。主题要建在「TCP 设备云」（接口里 `type=3`）。MQTT 设备云里的主题也会进米家，但路由器收不到它的指令。
4. **没重新同步**。新建或改名主题后，要在米家「我的 → 其他平台设备（新版：连接其他平台）→ 巴法 → 同步设备」。同步来的设备可能只出现在「巴法」这个列表里，不一定在米家首页；仍看不到就解绑巴法后重新绑定。
5. **没设昵称**。不影响同步，但小爱同学按昵称识别设备，建议设为「电脑」。
6. **米家绑定的是另一个巴法账号**。巴法云的手机号账号和微信账号可能是两个独立账号；米家里「巴法」授权登录的账号必须就是路由器私钥所属的那个账号，否则同步过来的是另一个账号的（空）设备列表。到米家解绑巴法，用同一种方式（例如同一个手机号）重新登录授权。

注意：v2.14.0 的「检查巴法云」把巴法云接口的真实返回格式解析错了，会误报「主题不存在」，网页和 App 里也看不到电脑；v2.14.1 / App 1.0.1 修复了解析，但浏览器会继续使用缓存里的旧脚本（固件内文件修改时间固定，路由器的网页服务器又不发禁止缓存的响应头），所以 v2.14.1 里仍可能看到误报。v2.14.2 起诊断脚本每次都重新加载、LuCI 页面换了新文件名，并对「不存在」的主题单独复核；检查结果最后一行会显示「诊断脚本版本」。如果升级后页面看起来没变化，在页面上按 Ctrl+F5（手机清除浏览器缓存）。

如果主题都正确、米家里仍然没有，问题在巴法云和米家之间（巴法的米家接入有时会出故障），可以先用 iOS App 的 Siri 指令或网页开机。

### 米家里的开关状态

米家显示的开关状态就是巴法云主题里存的最后一条消息。只靠手机发的指令，电脑自己关机、或者开机没成功时，米家会一直显示「已开启」。

所以路由器默认开启「同步开关状态到米家」：

- 每 30 秒探测一次每台电脑是否开机，状态和云端不一致时，用主题的 `/up` 后缀（只更新云端数据，不推送给订阅者）把真实的 `on` / `off` 写回巴法云，米家里的开关就跟着电脑走。
- 探测用 ARP 而不是 ping：Windows 防火墙默认不回 ping，但电脑开着就一定会应答 ARP。电脑的 IP 从路由器的 ARP 表和 DHCP 租约里找，固定 IP 的电脑也能用（只要它开机后跟路由器通信过一次）。
- 收到开 / 关指令后约 20 秒内不改写状态（够路由器做一轮探测），之后立刻写回电脑的真实状态，并且总会重写一次、带上新的时间戳。所以发出开机指令后，米家里的开关会先变回「已关闭」（电脑还在启动），电脑真正起来后再变成「已开启」；一直是「已关闭」就说明唤醒没成功。
- App 和手机网页发出开机指令后显示「开机中…」，直到路由器用晚于指令的时间戳写回 on 才显示「已开机」；3 分钟后电脑还没起来会显示「电脑没有响应开机指令」并给出排查提示。（v2.15.1 / App 1.0.2 起；之前的版本一发指令就显示「已开机」，并不代表电脑真的开了。）
- 米家里点「关闭」或说「关闭电脑」**不会关机**（路由器没法替电脑关机），约 20 秒后开关会变回「已开启」。
- 关机后状态变为「关闭」最多需要约 1 分钟。部分网卡在**睡眠**时会替系统应答 ARP（Windows 的「ARP 卸载」），睡眠中的电脑可能显示为「开启」。
- 不想要这个功能就在 LuCI 里取消勾选「同步开关状态到米家」，或者 `uci set remote-wol.main.sync_state='0'`。LuCI「运行状态」里能看到每台电脑当前的开机 / 关机判断和 IP。

## 工作原理

- `/etc/init.d/remote-wol` 校验配置（私钥只允许字母数字、MAC 统一成大写冒号格式、主题只允许字母数字且不重复、最多 8 个），然后由 procd 常驻运行 `/usr/share/remote-wol/bemfa.uc`。配置不完整时不启动，原因写进系统日志。
- `bemfa.uc` 用 ucode socket 模块（邻传已经内置）连接 `bemfa.com:8344`，发送 `cmd=1&uid=私钥&topic=主题1,主题2` 订阅。每 30 秒发一次 `ping` 心跳（巴法云 65 秒没收到数据就断开），75 秒收不到服务器任何数据就判定连接已死并重连。连不上时按 5 秒、10 秒……最长 2 分钟退避重试，校园网没认证时不会频繁外连；私钥被拒绝时每 2 分钟重试一次。
- 收到 `cmd=2&...&topic=主题&msg=on`（也接受 `on#参数`、带 `/set` 后缀的主题）时，调用 `/usr/share/remote-wol/wake MAC`；它用 `etherwake -b` 在 LAN 网桥（`br-lan`）上发送目标地址为 `ff:ff:ff:ff:ff:ff` 的二层魔术包。电脑睡眠后交换芯片早已忘了它的 MAC，广播才能保证送达；也不依赖电脑的 IP 和 ARP。
- 故意只用 `cmd=1`：`cmd=3` 会在订阅时补发主题的最后一条消息，每次断线重连都会误开机。
- 状态同步：向电脑 IP 的 UDP 9 端口（discard，电脑会直接丢弃）发 1 字节，让内核重新确认 ARP；下一轮读 `/proc/net/arp`，条目已解析（标志 `0x2`）即在线，解析失败的条目 MAC 变成全 0 即离线。写回用 `cmd=2&uid=私钥&topic=主题/up&msg=on|off`，只在状态变化、重新连上服务器、或指令宽限期结束时发送。只在 LAN 内发探测包，不产生额外外网流量。
- 状态写在内存盘 `/tmp/remote-wol/status.json`（不含私钥），LuCI 每 5 秒读取一次；私钥只在 `/etc/config/remote-wol`（权限 0600）。
- LuCI 的 ACL 只允许执行 `/usr/share/remote-wol/wake <参数>` 和读取状态文件；唤醒脚本会再校验一遍 MAC 格式，不接受其他参数。

## 安全提示

- 知道你的私钥和主题的人都能给你的电脑发开机指令（只能开机，不能做别的）。私钥泄露后在巴法云控制台重置即可，然后在路由器上更新。
- 巴法云 TCP 接口是明文协议，私钥会以明文经过网络。这是巴法云 TCP 协议本身的限制；最坏后果是别人能远程开你的机。
- 路由器不接收、也不执行任何除开机以外的指令。

## 故障排查

| 现象 | 处理 |
|---|---|
| 「立即唤醒」电脑也没反应 | 电脑侧问题：按「准备电脑」逐项检查 BIOS、网卡电源管理和快速启动；确认 MAC 是**有线网卡**的；确认网线插在路由器 LAN 口上 |
| 状态一直是「正在连接」或「连接断开」，原因是连接失败 / 超时 | 路由器连不上外网（校园网未认证或掉线），或校园网屏蔽了 8344 端口。先确认路由器能上网：`ping bemfa.com`；端口被封时只能换网络环境 |
| 状态是「巴法云拒绝了订阅」 | 私钥填错，或主题没在巴法云「TCP 设备云」里创建 |
| 页面显示「未运行」 | 没勾选启用、私钥为空，或没有一台电脑的 MAC 和主题都合法；`logread -e remote-wol` 看具体原因 |
| 米家里看不到设备 | 见上文「米家里看不到设备」，先点「检查巴法云」 |
| 巴法云发了 on，路由器状态里没有唤醒记录 | 确认消息是发到「TCP 设备云」的同名主题（MQTT 设备云是另一套主题），消息内容是 `on` |
| 有唤醒记录、显示已发送魔术包，但电脑没开 | 电脑侧问题，见下方「路由器发了唤醒包，电脑没开」 |
| 米家里找不到「电脑」 | 主题要建在「TCP 设备云」且以 `001` 结尾；改过主题或昵称后在米家「连接其他平台 → 巴法」里重新同步设备 |
| 米家开关状态不对 | 看 LuCI「运行状态」里这台电脑的开机 / 关机判断和 IP。显示「检测中」或没有 IP，说明路由器开机后还没见过这台电脑；刚发过指令的约 20 秒内状态不会被改写 |

### 路由器发了唤醒包，电脑没开

先看路由器的系统日志里电脑所连网口（如 `lan1`）在关机后的链路状态：`logread | grep "lan1: Link"`。

- 关机后 **Link is Down 之后不再 Up**：网卡关机后断电了。检查 BIOS 的 `ErP` / `EuP` / 深度节能是否关闭、`Wake on LAN` / `Power On By PCI-E` 是否开启；有的主板对板载网卡单独有一项「Onboard LAN 唤醒」。
- 关机后 **很快又 Link is Up - 10Mbps 或 100Mbps**：网卡已进入唤醒待命，BIOS 没问题，但它不认路由器发来的魔术包。依次检查：
  1. **MAC 地址是否被改过**。在电脑上运行 PowerShell：`Get-NetAdapter | Format-Table Name, InterfaceDescription, MacAddress, PermanentAddress`。如果 `MacAddress`（当前）和 `PermanentAddress`（出厂）不一样——例如在网卡高级属性里改过「网络地址 / Network Address」，或用过改 MAC 的工具——关机后网卡只认出厂 MAC。把路由器「远程开机」里这台电脑的 MAC 改成 `PermanentAddress`，或者把网卡的「网络地址」恢复为「不存在」。
  2. **网卡高级属性**（设备管理器 → 网络适配器 → 有线网卡 → 属性 → 高级），或 PowerShell `Get-NetAdapterAdvancedProperty -Name "以太网" | Format-Table DisplayName, DisplayValue`：
     - 「魔术封包唤醒 / Wake on Magic Packet」= 开启
     - Realtek：「关机 网络唤醒 / Shutdown Wake-On-Lan」= 开启；Intel：「从关机状态唤醒 / Wake on Magic Packet from power off state」= 开启
     - 「节能乙太网路 / Energy-Efficient Ethernet」「绿色乙太网路 / Green Ethernet」= 关闭
  3. **电源管理**页勾选「允许此设备唤醒计算机」和「只允许幻数据包唤醒计算机」。
  4. 改完后**正常关机一次**（不是重启）再试；网卡驱动设置在下一次关机时才写入网卡。

路由器侧可以抓包确认唤醒包确实从网口发出：`opkg update && opkg install tcpdump-mini`，然后 `tcpdump -i lan1 -e ether proto 0x0842`，再点一次开机，应看到发往 `Broadcast` 的 0x0842 包，内容是 6 个 `ff` 加 16 遍电脑 MAC。
